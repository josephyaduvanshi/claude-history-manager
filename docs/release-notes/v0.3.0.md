# Chronicle v0.3.0 — multi-provider, with auto-update

Chronicle started as a browser for Claude Code's session history. v0.3.0 makes it a browser for all three CLIs you might be running: Claude Code, Codex CLI, and Gemini CLI. Each provider's data is kept separate, so a Codex pin doesn't end up under Claude. The app also updates itself in place now, so the next version installs with one click instead of "open browser, download zip, drag into Applications, type sudo".

## What's new

### Codex and Gemini support

Reads JSONL rollouts from `~/.codex/sessions/<year>/<month>/<day>/rollout-*.jsonl` and JSON files from `~/.gemini/tmp/<project-dir>/chats/`. Switch between providers with the segmented control in the title bar, the menubar tile grid (`⌘⇧O`), or the View menu. Switching swaps the workspace list, session counts, smart folders, stats, tags, and pins to the active provider's data. Nothing leaks across.

The brand glyphs are the actual logos (Anthropic burst, OpenAI 6-petal swirl, Google Gemini 4-pointed star), template-tinted so they pick up whatever theme you're on. Attribution lives in `THIRD_PARTY_NOTICES.md`.

### Resume, routed per provider

Each CLI takes a different resume invocation. The launcher gets each one right:

- Claude → `claude --resume <uuid>`
- Codex → `codex resume <uuid>` (subcommand, not a flag — easy to get wrong)
- Gemini → `gemini --resume <uuid>` (full UUID, not the numeric index that renumbers as new sessions start)

Working directory is preserved.

### Transcript view, end to end

Codex and Gemini sessions render the same as Claude: message bodies, inline collapsible tool calls, real model names (`gpt-5.4`, `gemini-3-flash-preview`, etc., not the API host), Files Touched per provider's actual tool calls (`apply_patch`/`exec_command` for Codex, `write_file` for Gemini), Tools Used, TOC sidebar. Tool-only assistant turns no longer leave blank bubbles.

### In-app auto-update via Sparkle

`Check for updates…` no longer opens the browser. Click it and Chronicle downloads the new release, verifies an EdDSA signature against a public key embedded in the app, swaps the running bundle in place, and relaunches. No sudo prompt. No manual install. A tampered download fails verification before it touches your `/Applications` folder.

The signing key only exists as a GitHub secret in the release pipeline — every release zip is signed in CI, and the matching public key ships in the app. Updates remain user-triggered. There's still no background polling and no daemon.

### Search across all three

Title search and `/full:` FTS5 body search work on every provider. The active tab scopes the result set, so a Codex search returns Codex sessions only.

### Live indexing per provider

Per-provider watchers detect new sessions and tail in-flight files. Switching providers runs a fast catch-up walk so a session created while a watcher was inactive shows up within about five seconds. No restart needed.

### Per-provider data isolation

Every record (session, tag, pin, archive flag, custom title, note, smart folder) carries the provider it belongs to. v0.1.x records migrate to `provider=claude` automatically on first launch. iCloud sync preserves the tag end to end, so a Codex pin on Mac A doesn't show up under Claude on Mac B.

### UI polish

The provider segmented control matches the Sessions/Stats tab style: a subtle elevation pop for the active button, no brand-color fill. Same readability across every theme without depending on the accent's contrast.

## Compatibility

macOS 15 or newer. Universal binary (arm64 + x86_64), built against the macOS 26 SDK. The v0.1.x schema upgrades on first launch in under two seconds; existing Claude data is preserved and not re-bootstrapped. v0.1.x readers see v0.3.0 records as `provider=claude` and don't crash.

## Known wart

The "Resume in Ghostty" button triggers Ghostty's "Allow Ghostty to execute …" dialog every time you click it. That's a Ghostty security gate ([discussion #10203](https://github.com/ghostty-org/ghostty/discussions/10203)) for externally-invoked commands and can't be turned off in Ghostty's config. iTerm, Terminal, WezTerm, Alacritty, and Kitty don't have this prompt.

## Install or upgrade

```bash
brew update
brew upgrade --cask chronicle
```

Or grab `Chronicle-0.3.0.pkg`, `.dmg`, or `.zip` from the assets below. SHA256 checksums are in `Chronicle-0.3.0.shasums`.

If `brew upgrade` errors with "App source `/Applications/Chronicle.app` is not there" mid-upgrade — a known Homebrew Cask quirk — fall back to:

```bash
brew uninstall --cask chronicle --force
brew install --cask chronicle
```

After v0.3.0 is installed, the in-app `Check for updates…` flow handles every future upgrade without leaving the app.
